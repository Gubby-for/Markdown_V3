# ¿Que es un CMS?


> es un gestion de editor similar al SSG , no obstante tiene diferencias al SSG por ejemplo a la edición en tiempo real 






## ¿Cómo Funciona un CMS?
Se divide en dos partes:


1. **Backend (Area de administración):** ies donde se localiza la administración (usuarios, contraseñas, etc… )
2. **Frontend (Parte Visible):** es la visualidad del usuario  , la parte del interfaz del usuario.




----


## Tipos de CMS y Ejemplos


* **Codigo Abierto:** Gratuitos y altamnete pernsonalizables gracias a sus comunidades activas
    * *Ejemplos:* **WordPress**, **Drupal**.
* **Comerciales / Propietarios:** Soluciones de pago con soporte tecnico
    * *Ejemplos:* **Shopify** y **Wix**.
* **SaaS:** Alojados en servidores externos.


-----


## Comparacion de CMS y SSG

| Característica | CMS | SSG |
| :--- | :--- | :--- |
| **Forma de crear contenidos** | Paneles visuales, editores o bloques integrados | Escribiendo archivos de texto plano |
| **Base de datos** | Dinámica (MYSQL/MariaDB) | No utiliza |
| **Generación del HTML** | Dinámica (se genera en tiempo real) | Estática (se genera por anticipo) |
| **Servidor necesario** | Servidor con ejecución backend (PHP, Node.js) | Alojamiento web estático y simple (GitHub Pages, Vercel) |
| **Panel de administración** | Integrado de forma nativa y muy visual | Opcional o externo |
| **Conocimientos técnicos** | Bajos | Medios/Altos (requiere conocimientos) |
| **Seguridad** | Requiere mantenimiento seguido | Muy Alta |
| **Rendimiento** | Depende de la optimización del servidor, caché y base de datos. | Extremadamente rápido |
| **Actualización del contenido** | Instantánea y directa | Requiere recompilar y desplegar de nuevo el sitio web tras modificar los archivos. |
| **Publicación** | Directa desde el panel / servidor | Mediante un proceso de compilación (*build*) automatizado o manual. |
| **Ejemplos** | WordPress, Drupal, Joomla. | Hugo, Astro, Jekyll, Gatsby. |
